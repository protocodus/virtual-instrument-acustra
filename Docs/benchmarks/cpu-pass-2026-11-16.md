# CPU pass, 1.9.61 — 2026-11-16

Source 1.9.60 (`6a4826a`, main) against 1.9.61. Both changes are in
`sumAxialCells` and its caller `evaluateStringAxialStretch`, the axial stretch
sum that is the largest cost of a held note, and both leave every output
sample bit for bit as it was.

## What changed

1. **The contiguous path again in the Rack's layout.** The sum has a fast
   path that reads the delay line without masking while the cells it needs
   lie between the ring's start and its newest sample. It tested that against
   `newest = writeIndex - 1`. With `ACUSTRA_EXTENDED_SAMPLE_RATES`, the
   Rack build's layout, a line's write index runs over the whole 32768-sample
   capacity while the mask is the rate's active size, so `newest` sat outside
   the active ring three samples in four and the sum fell back to its masked
   path. `newest` is now masked into the ring. Every read masks, so the reads
   are the same; only the path that makes them changes. The native layout's
   write index already wraps at the mask, so nothing changes there.
2. **A table of the cells' places (`AxialCellTable`).** On the contiguous
   path, every sample, each interior cell's returning-wave age
   (`period - span · cell`) was converted to a whole sample offset and an
   interpolation weight. Both depend only on the loop's period and the cells'
   returning span, which hold their exact bits for as long as a note rings
   unbent. The sum now records the offsets and weights the first sample a loop
   meets a new pair of bits, computed by the same arithmetic, and reads them
   back while both bits hold. A bend, a slide, a new note or a change of the
   span writes the table again on its first sample. The table holds 256 cells
   a loop; the longest loop in the demos and stress phrases needs 138 (at
   22.05 kHz; 90 at 48 kHz, 80 from 96 to 384 kHz, 79 at 768 kHz), and a
   longer one sums without it.

`Acustra.StringAxialForce`'s new `cellTableIsAPureCache` renders a held
chord, a bend and a fresh note at 22.05, 48 and 96 kHz on two engines, one of
which forgets every table before each sample, and requires identical bits.
With the table's weight pointer left un-advanced on purpose, it fails at all
three rates.

## Builds

- **Native**: `g++ 13.3 -std=c++17 -O3 -DNDEBUG`.
- **Rack flags**: `clang++ 18 -std=c++17 -O2 -fno-builtin -fno-vectorize
  -fno-slp-vectorize -ffp-contract=off -msse3 -DJUKEBOX_SDK
  -DACUSTRA_EXTENDED_SAMPLE_RATES=1 -DNDEBUG`: a stand-in for Reason's
  `phdsp64` profile, whose backend compiles the bitcode itself, so this is an
  estimate of the device's CPU, not a measurement of it.

`acustra::Performer`, as `Tools/RenderPresetDemos.cpp` plays them, timed with
`CLOCK_THREAD_CPUTIME_ID` on the calling thread, baseline and candidate
alternating in each round. Development machine: 4-core Intel Xeon (cloud VM),
Linux; not Reason's CPU and not a guarantee on another processor.

Instructions (callgrind) for demo 1, Dreadnought Steel:

float-to-integer conversions. In the Rack build, where the sum had been on
its masked path most of the time, both changes add up.

## Where the time goes now

Rack flags, demo 1, by instructions: the axial stretch about 44%,
`process` and its per-sample work about 23%, the body about 12%, the bridge
about 8%. The rest of the stretch is the squared-slope arithmetic itself,
which the 2026-11-09 decision keeps at four cells per period.

## Considered and not shipped

- **Two cells per period instead of four** (the stride doubled): −20.9% on
  the Rack flags and −15.1% natively against 1.9.60, on top of this pass. It
  does not null (−27 to −57 dB residual on the demos) and the owner kept four
  cells by ear on 2026-11-09 (`Docs/decisions.md`), so it is out to the ear
  again as a blind A/B against 1.9.60 and ships only if chosen there.
- **The stretch evaluated every other sample**, spreading each change over
  two samples (−25%) or extrapolating it (−26%). Both fail
  `Acustra.StringAxialForce`: the first folds the source at the reduced
  rate, which the every-sample evaluation exists to prevent; the second also
  fails the ring's decay, the wound G's loss, the invalid-stretch recovery
  and the uniform retarded source. Withdrawn before any listening.
- **The generic-stride read loop's register spills** (108 instructions per two
  groups in the Rack proxy). Reason's backend allocates the registers, so a
  rearrangement tuned on the proxy need not carry over; not pursued.
