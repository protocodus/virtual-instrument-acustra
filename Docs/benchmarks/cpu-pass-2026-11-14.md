# CPU and Rack-alignment pass, 1.9.48 & 1.9.49 — 2026-11-14

Sources 1.9.47 (`a7b3bd0`) against 1.9.48 (`e49be52`) and 1.9.49, measured on Apple M-series ARM64
(macOS, Apple Clang) in 64-frame blocks through `acustra::Performer` and
`acustra::AcustraEngine`. Other builds shared the 10-core machine during the
run, so every timing below is calling-thread CPU time
(`clock_gettime(CLOCK_THREAD_CPUTIME_ID)`) averaged over six alternating
`A/B, B/A` rounds in a single process, and every optimization was kept only
when its rendered output matched the post-bugfix reference to the bit.

## Method

- **Two builds.**
  - **Native Release**: `-std=c++17 -O3 -fno-builtin -DNDEBUG -Wall -Wextra -Wpedantic -Werror`.
  - **Rack flags (`JUKEBOX_SDK`)**: `-std=c++17 -O2 -fno-builtin -DJUKEBOX_SDK -DNDEBUG -Wall -Wextra -Wpedantic -Werror`, matching the Jukebox `phdsp64` compilation profile (`__BIGGEST_ALIGNMENT__ == 8`, `-O2`, `-fno-builtin`).
- **Heap alignment.** `static_assert(alignof(acustra::AcustraEngine) <= 8)` and
  `static_assert(alignof(acustra::Performer) <= 8)` hold after removing
  over-aligned `alignas(16)` member specifiers in `BodyBank` and `RoomAmbience`
  and reading SIMD lanes through `aligned(4)` / `aligned(8)`, `may_alias` vector
  typedefs.
- **Stack-spill check.** Disassembly of `AcustraEngine.cpp` under ARM64 `-O3 -fno-builtin`,
  x86_64 `-O3 -fno-builtin`, and `JUKEBOX_SDK` `-O2 -fno-builtin` confirmed zero
  stack allocation (`sub sp, sp, ...` absent) in `BridgeLoad::advanceModes`,
  `BodyBank::CaptureFilter::render`, `BodyBank::render`, and
  `RoomAmbience::process`.
- **Exactness.**
  1. `AcustraCpuOptimizationComparison`: **123/123 scenarios passed** across
     8 kHz to 384 kHz with zero bit differences in Main L/R, Piezo, and
     serialized public engine state words.
  2. Raw float renders across all **8 factory presets × {44.1, 48, 96, 192 kHz} × {cold, warm pitch/body cache}**:
     **0 bytes different (`memcmp == 0`)** in both Native Release and Rack flags.

## Shipped optimizations (all bit-exact)

1. **Paired dual-polarisation string loops (`StringLoop::advancePair`).** Each
   string's `{normal, parallel}` wave loops — both active loops and retained
   tail loops — step together in two-lane `Double2` vectors across the upper
   dispersion allpasses, second dispersion, standard and rate-remapped loss
   filters, bending loss, constant loss, primary dispersion, and loop/release
   gain scaling.
2. **ARM64 4-wide axial stretch cells (`sumAxialCells`).** Enabled 4-lane
   `float` SIMD on `__aarch64__` / `__ARM_NEON` alongside x86 SSE, loading the
   8 returning-wave samples via paired 64-bit loads + shuffles, adding fast
   vector-load paths for `stride == 1` and `stride == 2` outgoing taps, updating
   inter-sample history with a vector `ext` shuffle, and accumulating the four
   squared slopes in scalar association order so ARM64 FMA contraction matches
   the scalar reference to 0 ULP.
3. **Two-lane bridge modes (`BridgeLoad::advanceModes`) and stereo capture
   biquads (`BodyBank::CaptureFilter::render`).** Enabled `Double2` modal
   stepping across ARM64, x86_64, and `JUKEBOX_SDK`, and stepped `{left, right}`
   capture biquad cascades in paired `Double2` lanes with a branchless IEEE-754
   `< 1.0e-30` (`0x39b4484bfeebc2a0`) flush while preserving inter-section
   `float` rounding.
4. **Paired modal admittance in the coupled tuning solve (`coupledPolarisationDetune`).**
   Stored precomputed bridge mode terms in structure-of-arrays layout and
   evaluated modal admittances two modes at a time in `Double2`, halving
   double-precision divisions per evaluation while accumulating in the original
   mode order.
5. **Silent-stage pruning and precomputed rate ratios.** Tracked exact zero-state
   rest on `BridgeLoad`, `BodyBank`, and `renderPiezo` (`piezoSilent_`), added an
   exact `value == target` fast return in `settlingGlide`, cached sample-rate
   ratios in `prepare()`, and guarded inactive per-sample release, excitation,
   and stationary fret-motion helpers in `AcustraEngine::process`.

## Follow-up exact axial-stretch pass, 1.9.48 → 1.9.49

1. **Exact-bit per-polarisation `LoopGeometry` cache + 2-lane vector final-cell division (`evaluateStringAxialStretch`).**
   Each loop's settled axial-stretch cell geometry (`shear`, `width`, `cells`, `lastWidth`, `returningSpan`, `returningScale`, `shearPeriod`, `outgoingEndAge`, `lastOutgoingDenom`, `lastReturningDenom`) is cached on `(periodBits, roundTripBits, stride)` with `outgoingScale` precomputed in `redesignStringAxialForce`, eliminating 12 scalar divisions per string per settled sample and reducing the final cell's two boundary divisions to one two-lane `Float2` vector division.
2. **Hoisted `stride` specialization and vector byte-offset addressing (`sumAxialCells`).**
   Hoisted `stride == 1 / 2 / 3 / generic` dispatch outside the inner 4-cell group loop, added a two-load + single-shuffle fast path for `stride == 3` (all four wound strings at 48 kHz), and replaced the 4-element `int back[4]` stack copy + scalar shifts with direct SIMD negative byte offsets (`-(whole << 2)`).
3. **Cold `fallbackVoiceTension` extraction, immediate-offset member ordering, and precomputed tail thresholds.**
   Moved cold `fallbackVoiceTension` out of line (`ACUSTRA_NOINLINE`) so `evaluateStringAxialStretch` makes zero external calls, placed `StringAxialForce::ring` and `AxialContactArrivals::force` behind per-sample scalar flags for ARM64 immediate-offset addressing, precomputed `tailQuietLimitSamples_` / `tailUnfedLimitSamples_` in `prepare()`, and unrolled the 4-section axial output band filter.
