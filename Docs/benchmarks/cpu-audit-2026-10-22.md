# Acustra CPU audit, 2026-10-22

The canonical reference is `bec9d409b3689e637ac2835fd69db3863a6195c2`
(1.6.3). No production DSP optimization is retained from this audit. The accepted
velocity/strum dynamics, body/decay model, quality choices, and controls stay
unchanged.

## Scope and prior evidence

The October 5, 7, 8 and 16 CPU reports were reviewed before selecting experiments.
Earlier work already rejected scalar/coefficient hoists, bridge and capture SIMD,
room double mirrors, stationary contact bypasses, and intrinsic-transition
outlining. The principal active costs remain the string recurrences, the passive
bridge modes, and the radiation bank. The new fixed player body load is evaluated
while configuring coefficients, not for each sample. The latest velocity/strum
laws operate at contact and do not add a new audio-rate solver.

Two further low-risk compiler/recurrence candidates were screened. They were
rejected, rather than adding complexity for an unsubstantiated speed claim.

| Candidate | Equal-case geometric-mean charged CPU saving | Decision |
| --- | ---: | --- |
| Skip the double delay-follow recurrence only when progress already equals its exact target | −0.0113% | Reject: no useful gain |
| Let the compiler choose whether to inline the string recurrence | −0.0029% | Reject: no useful gain; the declaration also records a historical SDK outlining regression |

Positive saving means less CPU. Each screen includes 20 cells and 90,000 paired
callbacks: 48/96 kHz host rates, 64 host frames represented by 128 engine frames
at the shipped 2x quality; Finger/Pick; held chord, repeated strums, note runs,
release tail, and bends. The same C++17 Apple Clang 21 Release flags and frozen
headers are used for each pair. Main L/R and requested Piezo output are compared
with `memcmp` after every callback; all 34,560,000 values per candidate match.

The explicit engine gain is 0.8, Room 0.1, mixed Piezo 0.2 and Release Noise 0.1.
This is engine/Performer-only evidence: it excludes output-rate conversion,
Rack property handling, Reason scheduling, and target translation. It is not a
measurement of the complete default patch's CPU. Event dispatch is included;
preparation, comparisons, reports and CSV writes are outside timing. Callback
order alternates within each pair. Both wall and charged thread CPU clocks are
recorded for every callback. Initial setup callbacks are retained rather than
presented as an independently warmed steady-state result.

Task builds ran concurrently during these screens; these are selection evidence,
not final quiet-machine timing or realtime guarantees. The small differences
above are not significant improvements. Raw timing and failing-performance
experiments are retained, not rerun until a favorable number appears.

Both candidates also pass the existing quick dual-build exact audio/public-state
matrix: 23 configurations, including 96 kHz, connected articulations, release
tails, coefficient transitions, lifecycle/reset and alternate block partitions.
No model is retuned and no tolerance is loosened.
